## 1. 要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Ubuntu 20.04+ / Debian 11+（x86_64 或 arm64） |
| Node.js | **≥ 22.5**（需要内置 `node:sqlite`） |
| 内存 | ≥ 512 MB（2 GB 更稳） |
| 磁盘 | ≥ 500 MB（要放镜像的话另算，ISO 约 1.3 GB） |
| 权限 | root |

检查 Node：

```bash
node -v            # 需要 v22.5.0 或更高
node -e "require('node:sqlite')" && echo "sqlite OK"
```

> Node 22 会打印一条 `SQLite is an experimental feature` 警告，正常，可以忽略。

没有 Node 的装法（任选一个）：

```bash
# 官方二进制（最简单，不依赖发行版仓库）
curl -fsSL https://nodejs.org/dist/v22.22.0/node-v22.22.0-linux-x64.tar.xz -o /tmp/node.tar.xz
tar -xJf /tmp/node.tar.xz -C /usr/local --strip-components=1
node -v

# 或 NodeSource
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs
```

## 2. 一键安装

```bash
# 把项目放到服务器上（git clone 或 scp 上传都可以）
git clone https://github.com/PUUPXXP/web-miner-monitor.git
cd web-miner-monitor

# 安装（默认端口 32001，随机生成管理员密码）
sudo bash deploy/install.sh

# 指定端口和密码
sudo bash deploy/install.sh --port 32001 --password 'YourStrongPass'
```

装完会打印：

```
================================================
 部署完成
   地址：http://1.2.3.4:32001
   账号：admin
   密码：xxxxxxxxxxxx
================================================
```

浏览器打开这个地址就能用了。

> 国内服务器常常连不上 GitHub，这时先在本地 `git archive` 打包再上传：
>
> ```bash
> # 本地
> git archive --format=tar.gz -o /tmp/app.tar.gz HEAD
> scp /tmp/app.tar.gz root@1.2.3.4:/tmp/
> # 服务器
> mkdir -p /root/wm && tar -xzf /tmp/app.tar.gz -C /root/wm
> bash /root/wm/deploy/install.sh --source-dir /root/wm
> ```

## 3. 安装脚本做了什么

| 位置 | 内容 |
| --- | --- |
| `/opt/web-miner-monitor` | 代码（属主 `minermon`） |
| `/var/lib/web-miner-monitor` | 数据库、日志、初始密码文件（属主 `minermon`，权限 750） |
| `/etc/web-miner-monitor.env` | 环境变量（**权限 600**，含管理员密码） |
| `/etc/systemd/system/web-miner-monitor.service` | 服务单元，`Restart=always` + 开机自启 |

服务以专用系统用户 `minermon` 运行，**不用 root**。

环境变量文件长这样，改完 `systemctl restart web-miner-monitor` 生效：

```bash
MM_PORT=32001
MM_HOST=0.0.0.0
MM_ADMIN_USER=admin
MM_ADMIN_PASSWORD=xxxxxxxx
MM_DATA_DIR=/var/lib/web-miner-monitor
MM_LOG_DIR=/var/lib/web-miner-monitor/logs
MM_PUBLIC_URL=http://1.2.3.4:32001
MM_AGENT_AUTO_REGISTER=true
```

> `MM_ADMIN_PASSWORD` 只在**首次启动、数据库里还没有管理员**时生效。
> 已经建号以后要改密码，去控制台「设置 → 修改密码」。

## 4. 常用运维命令

```bash
systemctl status web-miner-monitor      # 状态
systemctl restart web-miner-monitor     # 重启
journalctl -u web-miner-monitor -f      # 实时日志
tail -f /var/lib/web-miner-monitor/logs/server.log   # 应用日志

# 备份（数据库 + 配置）
tar -czf ~/mm-backup-$(date +%F).tar.gz \
  /var/lib/web-miner-monitor/monitor.sqlite* /etc/web-miner-monitor.env

# 恢复
systemctl stop web-miner-monitor
tar -xzf ~/mm-backup-2026-11-20.tar.gz -C /
systemctl start web-miner-monitor
```

> 备份 SQLite 时最好先停服务，或者用 `sqlite3 monitor.sqlite ".backup /tmp/x.db"` 热备。

## 5. 升级

```bash
cd /path/to/web-miner-monitor
git pull
sudo bash deploy/install.sh --port 32001      # 重新执行即可，幂等
```

**注意**：重装会重写 `/etc/web-miner-monitor.env`。如果之前的密码是脚本随机生成的，
它会生成新的——但数据库里已有管理员，所以**旧密码继续有效**，新密码不生效。
想强制换密码就去控制台改。

数据目录 `/var/lib/web-miner-monitor` 不会被覆盖。

## 5.5 忘记密码 / 重置密码

`MM_ADMIN_PASSWORD` **只在数据库里还没有管理员时生效**。已经建号以后再改环境变量是没用的。

重置（不用重装、不丢数据）：

```bash
sudo bash deploy/reset-password.sh 'NewPass123'
# 指定用户
sudo bash deploy/reset-password.sh 'NewPass123' --user admin
```

脚本会：停服务 → 用应用自己的 scrypt 实现重算哈希 → 写库 → 起服务 → 健康检查。

也可以登录后在控制台「设置 → 修改密码」改。

> 登录连续失败 10 次会锁定该 IP 5 分钟。急着登录可以 `systemctl restart web-miner-monitor` 清掉锁定计数（重启后计数归零）。

## 5.6 镜像自动构建（服务器出 ISO）

启用后，服务器自己构建 MinerOS 镜像，控制台「系统镜像」页直接下载，不用本机再跑构建。

### 启用

```bash
sudo bash deploy/install.sh --with-iso-build --port 32001 --password '你的密码'
```

会装上：

| 单元 | 作用 |
| --- | --- |
| `mineros-build.service` | 一次性构建任务（Debian 12 chroot，增量复用） |
| `mineros-autobuild.timer` | 每 10 分钟检查源码指纹，变了就触发构建 |
| `/etc/sudoers.d/web-miner-monitor-build` | 只允许面板用户启动这两个 unit |

### 怎么工作

```
代码更新 ──► 指纹变化 ──► 10 分钟内自动构建 ──► os/dist/*.iso ──► 控制台下载
```

- 构建在 `/var/lib/mineros-build` 里做，**不往宿主机装任何打包工具**
- 第一次要 debootstrap Debian 12 + 装 live-build（约 5-10 分钟）
- 之后每次复用 chroot 和 live-build 缓存，主要耗时是 squashfs 压缩
- 源码没变化时不会重复构建

### 手动操作

```bash
systemctl start mineros-build              # 立即构建
systemctl status mineros-build             # 看状态
journalctl -u mineros-build -f             # 跟日志
cat /var/lib/mineros-build/status.json     # 进度/日志尾部（控制台也读这个）
ls -lh /opt/web-miner-monitor/os/dist/     # 产物
```

控制台「系统镜像」页有「立即构建」按钮，进度条和日志都在那里看。

### 资源与时间

| 项目 | 参考值（2 核 / 1.8 GB / USTC 镜像） |
| --- | --- |
| 首次构建 | 约 40-60 分钟 |
| 后续构建 | 约 20-35 分钟 |
| 磁盘占用 | chroot + 缓存约 6-8 GB，产物 1.3-1.6 GB |
| 内存峰值 | 约 1 GB（zstd 压缩，比 xz 省一半以上） |

构建以 `Nice=19` + `IOSchedulingClass=idle` 运行，尽量不抢线上服务的 CPU。

### 换镜像源

默认自动选 USTC / 清华 / 阿里云里最快的（国内服务器直连 deb.debian.org 只有 ~20 KB/s，构建会卡死）。
想固定某个源：

```bash
sudo sed -i 's#^#Environment=MM_DEBIAN_MIRROR=http://mirrors.ustc.edu.cn/debian\n#' /etc/systemd/system/mineros-build.service
```

或在 `/etc/systemd/system/mineros-build.service` 的 `[Service]` 下加：

```ini
Environment=MM_DEBIAN_MIRROR=http://mirrors.ustc.edu.cn/debian
Environment=MM_SQUASHFS=zstd
```

`MM_SQUASHFS` 可选 `xz`（最小）/ `zstd`（最快，默认）。

## 6. 加 HTTPS（强烈建议）

控制台是走 HTTP 明文传密码的。放在公网上，尤其有公网 IP 的时候，建议套一层 HTTPS。

服务器已有域名 + Let's Encrypt 证书的话，用 `deploy/nginx-https.conf.example` 即可：

1. 应用退到本机端口：

   ```bash
   sed -i 's/^MM_PORT=.*/MM_PORT=32002/; s/^MM_HOST=.*/MM_HOST=127.0.0.1/' /etc/web-miner-monitor.env
   systemctl restart web-miner-monitor
   ```

2. 配 nginx（把域名和证书路径换成你自己的）：

   ```bash
   cp deploy/nginx-https.conf.example /etc/nginx/sites-enabled/miner.conf
   # 编辑 server_name / ssl_certificate* 三项
   nginx -t && systemctl reload nginx
   ```

3. 访问 `https://你的域名:32001`

没有域名的话，也可以只让固定 IP 访问（见下一节），或自己签张证书（浏览器会提示不受信任）。

## 7. 防火墙 / 安全组

**云服务器有两层**，两层都要放行：

```bash
# 1) 系统防火墙
ufw allow 32001/tcp          # 如果开了 ufw
# 或 firewalld
firewall-cmd --permanent --add-port=32001/tcp && firewall-cmd --reload
```

```text
2) 云厂商安全组（阿里云/腾讯云控制台）
   入方向：TCP 32001，授权对象建议填你自己的公网 IP/32，而不是 0.0.0.0/0
```

只给自己用的场景，最省事的加固就是**安全组只放行你的家宽 IP**。

## 8. 排错

**服务起不来**

```bash
journalctl -u web-miner-monitor -n 50 --no-pager
```

| 报错 | 原因 |
| --- | --- |
| `ERR_UNKNOWN_BUILTIN_MODULE: node:sqlite` | Node 版本 < 22.5，升级 Node |
| `EADDRINUSE` | 端口被占：`ss -tlnp \| grep 32001` |
| `EACCES` 写数据目录 | 确认 `/var/lib/web-miner-monitor` 属主是 `minermon` |
| `Cannot find module` | 代码不完整，重新 `install.sh` |

**能本机访问，外面打不开**

```bash
curl http://127.0.0.1:32001/api/health    # 服务器上自测
```
- 本机通、外网不通 → 安全组/防火墙没放行
- 本机也不通 → 看服务日志

**矿机连不上控制台**

矿机的 `rig.conf` 里 `SERVER_URL` 要填控制台的**公网地址**，并且 32001 要对矿机所在网络开放。

## 9. 卸载

```bash
sudo bash deploy/install.sh --uninstall
```

只删服务和代码，`/var/lib/web-miner-monitor`（数据库）会保留，删干净再手动：

```bash
rm -rf /var/lib/web-miner-monitor /etc/web-miner-monitor.env
userdel minermon
```
