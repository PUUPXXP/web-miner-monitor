# 挖矿知识与参数（Monero / Pearl）

本文件记录本项目内置的币种、矿工、矿池、API 字段与收益公式来源，方便你核对和调整。
数据整理于 **2026-11**，币圈变化快，请以矿池/矿工官方最新公告为准。

---

## 1. 两个币种

### Monero（XMR · 门罗）

| 项目 | 值 |
|---|---|
| 算法 | **RandomX**（矿工参数通常写 `rx/0`） |
| 适合硬件 | **CPU**。RandomX 为抗 ASIC/GPU 设计，显卡挖 XMR 性价比很低，建议只用 CPU（Ryzen / EPYC / i9 等） |
| 出块时间 | 约 120 秒 |
| 区块奖励 | 主排放结束后为固定 **0.6 XMR** + 手续费（尾部排放） |
| 地址 | 以 `4` 开头的 95 位地址 |
| 项目 | https://www.getmonero.org/ |
| 浏览器 | https://xmrchain.net/ · https://moneroblocks.info/ |
| 网络数据 | `GET https://moneroblocks.info/api/get_stats` → `{hashrate, difficulty, height, last_reward}` |
| 价格 | CoinGecko `monero` |

**推荐矿工：XMRig 6.26+（Windows）**

- 下载：https://github.com/xmrig/xmrig/releases（`xmrig-6.26.0-windows-x64.zip`）
- 常用命令行（本系统自动生成）：

```bat
xmrig.exe -o pool.supportxmr.com:3333 -u 4YOUR_WALLET -p x -a rx/0 --rig-id 机房A-01 ^
  --http-host 127.0.0.1 --http-port 3333 --no-color --print-time 30
```

- HTTP API：`GET http://127.0.0.1:3333/2/summary`
  - `hashrate.total` = `[10 秒, 60 秒, 15 分钟]` 算力（H/s）
  - `results.shares_good` / `results.shares_total` → 拒绝数 = total − good
  - `connection.pool`、`uptime`、`algo`
- 若设置了 `--http-access-token`，请求需带 `Authorization: Bearer <token>`
- 也可以把 `--http-host/--http-port` 换成 `config.json` 的 `http` 段，效果相同

**门罗常用矿池（2026-11）**

| 矿池 | 地址 | TLS |
|---|---|---|
| MoneroOcean | `gulf.moneroocean.stream:10128` | 否（TLS 用 `20128`） |
| SupportXMR | `pool.supportxmr.com:3333` | 否（TLS 用 `443`） |
| 2Miners | `xmr.2miners.com:2222` | 是：`12222` |
| HeroMiners | `monero.herominers.com:10191` | 是：`1118` |

### Pearl（PRL）

| 项目 | 值 |
|---|---|
| 定位 | 独立 L1 PoW 链，**Proof-of-Useful-Work**：用 GPU 做矩阵乘法（AI/GEMM 类负载）产生 ZK 证明作为工作量 |
| 算法 | **PearlHash**（`pearlhash`） |
| 适合硬件 | **NVIDIA GPU**（RTX 20 系及以上；官方/矿池普遍只优化 NVIDIA，AMD 支持有限） |
| 主网 | 2026-04-27 上线，`pearld` 全节点 + `oyster` 钱包 |
| 出块 | 目标 **194 秒**（约 3 分 14 秒） |
| 地址 | 以 `prl1` 开头 |
| 区块奖励 | 平滑衰减（无减半），见下方公式 |
| 官网 | https://pearlresearch.ai/ |
| 浏览器 | https://explorer.pearlresearch.ai/ |
| 社区 | Discord `discord.gg/joinpearl` · X `@prlnet` |
| 网络数据 | `https://server.miningpoolstats.stream/data/pearl.js`（可能被网络屏蔽，失败不影响系统） |
| 价格 | Gate.io `PRL_USDT`（CoinGecko 可用时优先） |

> ⚠️ 注意区分：只有「`prl1` 地址 + PearlHash 算法」的 Pearl 才是这个 GPU 挖矿链；历史上还有同名的 ERC-20 代币，不能挖。

**奖励公式（已验证与链上一致）**

```
总量 TOTAL = 2,100,000,000 PRL，常数 C = 650,226

累计产出(h) = TOTAL × h / (h + C)
区块补贴(h) = TOTAL × C / ((h + C) × (h + C − 1))
```

例：高度 145,131 时区块奖励 ≈ **2,158.54 PRL**（与链上 coinbase 一致）。
本项目用它计算「日预估收益」：`算力占比 × 每日出块数 × 区块补贴 × 价格`。

**推荐矿工：PeakMiner 2.20+**

- 下载：https://github.com/peakminer/peakminer/releases（`peakminer-2.20.9-windows-x86_64.zip`）
- 本系统生成的命令：

```bat
peakminer.exe --coin pearl -o prl.kryptex.network:8048 -u prl1YOUR_WALLET.机房A-01 --api-port 4068 --keepalive
```

- HTTP API（字段文档化，最完整）：
  - `GET http://127.0.0.1:4068/summary`
  - `hashrate`（H/s）、`power_w`、`accepted_shares`、`invalid_shares`、`pool.url`、`uptime`
  - `gpus[]`：`id / name / hashrate / temperature_c / fan_pct / utilization_pct / power_w / core_clock_mhz / mem_clock_mhz / pci_bus_id / accepted_shares / invalid_shares`
- 可选 `--api-key <secret>`（除 `/health` 外都需要带 `X-API-Key`）

## 2. 矿工 API 与本系统的解析

采集端每次心跳（默认 5 秒）会：

1. `nvidia-smi` 取所有卡的 温度/风扇/功耗/利用率/显存/频率；
2. 向矿工 HTTP API 请求统计（端口取自飞行表）；
3. 解析出总算力、份额、每卡数据；
4. 再上报给服务端。

各矿工解析器在 `agent/miner.js` 的 `PARSERS` 中，已内置：

| family | 接口 | 关键字段 |
|---|---|---|
| `xmrig` | `/2/summary` | `hashrate.total[]`、`results.shares_good`、`results.shares_total`、`connection.pool` |
| `peakminer` | `/summary` | `hashrate`、`gpus[]`、`accepted_shares`、`pool.url` |
| `srbminer` | `/` | `algorithms[].pool.hashrate/accepted/rejected` |
| `bzminer` | `/api/snapshot` | `devices[]`、`shares` |
| `onezero` | `/summary` | `devices[]` / `hashrate`（兼容多版本字段） |
| `wildrig` | `/` | `GPUs[]`、`Hashrate` |
| `custom` | 默认按 XMRig 协议 | 如无 API，自动退回**日志解析** |

日志兜底：会从最后 25 行里找 `speed 10s/60s/15m … H/s`、`accepted … rejected …`。
如果你的矿工日志格式不同，可以在 `agent/miner.js` 里加一个解析器（几十行）。

## 3. 显卡监控说明

### NVIDIA

一条命令取全部字段：

```bat
nvidia-smi --query-gpu=index,uuid,name,temperature.gpu,fan.speed,utilization.gpu,memory.used,memory.total,power.draw,power.limit,clocks.sm,clocks.mem,pstate --format=csv,noheader,nounits
```

- `[N/A]` 是合法值（笔记本、虚拟机、WDDM 下常见），解析时必须容忍；
- 卡序号重启后可能变化，长期统计建议用 `uuid`（本项目已存 `pci_bus_id` 作为辅助）。

### AMD（Windows）

Windows 下没有 `rocm-smi`，能稳定拿到的只有：

- `Get-CimInstance Win32_VideoController`：型号、驱动、显存（`AdapterRAM` 会溢出，仅供参考）
- 性能计数器 `\GPU Engine(*)\Utilization Percentage`：利用率（按 `luid/phys` 聚合）

**温度 / 风扇 / 功耗** 只能由矿工 API 提供（PeakMiner `gpus[].temperature_c` 等），
本项目会自动用矿工上报的每卡数据补齐。

## 4. 超频 / 功耗（NVIDIA）

本系统通过 `nvidia-smi` 下发，需要管理员权限（采集端以 SYSTEM 运行，天然满足）：

| 设置 | 命令 |
|---|---|
| 功耗上限 | `nvidia-smi -i 0 -pl 250` |
| 锁定核心频率 | `nvidia-smi -i 0 -lgc 2100` |
| 锁定显存频率 | `nvidia-smi -i 0 -lmc 5001` |
| 风扇转速 | `nvidia-smi -i 0 -fs 70` |
| 恢复默认 | `nvidia-smi -i 0 -rgc` / `-rmc` |

注意：

- 不同驱动/卡型对 `-lgc`/`-lmc`/`-fs` 支持不同，失败会在矿机事件里提示；
- 频繁写入 `-pl` 可能触发驱动重置，本系统只在启动/下发命令时应用一次，不会轮询写入；
- 社区更常用 MSI Afterburner 做精细超频，但它没有稳定的命令行接口，故本项目不集成。

## 5. 收益估算

总览页的「日预估收益」计算方式：

```
算力占比 = 本机（本币种）算力 / 全网算力
每日出块 = 86400 / 出块时间
日产出   = 算力占比 × 每日出块 × 区块奖励
日收入   = 日产出 × 币价(US$)
日电费   = 功耗(kW) × 24 × 电价(默认 0.7 元/度)
净收益   = 日收入 − 日电费
```

- 门罗：出块 120 秒、奖励 0.6 XMR（网络接口给出 `last_reward` 时以接口为准）
- Pearl：出块 194 秒、奖励按上面的衰减公式计算
- 全网算力 / 币价拿不到时该项显示为空，不会报错
- 这是**参考值**：矿池手续费、难度波动、孤块、电费都会影响真实收益
