## 1. 在线升级中心

控制台左侧「配置 → 在线升级」，地址 `#/updates`。

页面分四个标签：

| 标签 | 作用 |
| --- | --- |
| **升级包** | 已上传的所有版本，可删除、可直接下发 |
| **矿机版本** | 每台矿机当前的 系统 / 采集端 / 挖矿程序 版本，落后会标「有更新」，可单台升级 |
| **升级记录** | 每次下发的进度（下载 → 校验 → 替换 → 重启），失败会显示原因 |
| **制作升级包** | 打包命令速查 |

顶部五个数字：升级包总数、采集端版本、可升级矿机数、待升级矿机、进行中任务。

> 升级任务是**异步**的：点「开始升级」后马上返回，矿机在下次心跳（默认 5 秒）领取命令，进度实时回传，页面自动刷新。

## 2. 三种升级包

| 类型 | 用途 | 包内容 | 升级后动作 |
| --- | --- | --- | --- |
| **挖矿程序** `miner` | XMRig / SRBMiner / lolMiner… 出新版 | 新版可执行文件 | 原子替换 → 按当前飞行表重启矿工 |
| **采集端** `agent` | 监控采集程序自身 | `agent/` + `shared/` 目录 | 替换 → 重启采集端服务 |
| **系统组件** `system` | 驱动、CUDA、额外工具 | 任意文件 + `install.sh` / `install.ps1` | 执行安装脚本（自动传入备份目录） |

平台分 `win32` / `linux` / `any`：Windows 矿机和 MinerOS 矿机会各自只看到与自己平台匹配的包。

> **不传包也能升级采集端**：采集端升级可以完全跳过上传——服务器内置了当前版本的采集端包（`/api/agent/bundle.tar.gz`），
> 在「在线升级中心」或「系统镜像」页直接点「升级采集端」即可。

> **系统组件的脚本要匹配平台**：Windows 矿机只接受 `install.ps1`，MinerOS 只接受 `install.sh`；用错平台会明确报错，不会误执行。

## 3. 制作升级包

### 方式 A：命令行（推荐）

```bash
# Windows 矿机的 XMRig 新版
node scripts/make-update-package.js --id xmrig --version 6.26.0 --platform win32 --dir C:\miners\xmrig-6.26

# MinerOS（Linux）矿机的 SRBMiner
node scripts/make-update-package.js --id srbminer --version 2.9.5 --platform linux --dir /opt/miners/srbminer-2.9.5

# 指定包内可执行文件名（自动识别不到时）
node scripts/make-update-package.js --id gminer --version 3.44 --platform win32 --dir .\gminer --entry miner.exe
```

脚本会在 `updates/<类型>/<名称>/<版本>/` 下生成 `tar.gz` + `manifest.json`，服务器**自动扫描**即可见，无需重启。

### 方式 B：控制台上传

「在线升级中心 → 上传升级包」，填 类型 / 名称 / 版本 / 平台，选 `tar.gz` 或 `zip`。上传时服务器会计算 SHA256。

### 包结构约定

```
xmrig-6.26/            ← 建议用「程序名-版本」作为根目录
├── xmrig.exe
└── ...（同目录的其他文件）
```

打包时保留这一层根目录即可；采集端解包后会自动去掉单层根目录再安装。

## 4. 下发升级与回滚

### 下发

「升级包」标签页 → 某版本「下发升级」→ 勾选矿机（不选=全部）→ 开始升级。

或者「矿机版本」标签页：落后的矿机直接点「升级矿工」/「升级采集端」。

### 矿机端做了什么

```
下载（带 x-rig-token）
  → 校验 sha256（不符立即中止，不会改动现有文件）
  → 解压到 staging
  → 备份当前版本 → 写入新版本目录
  → 原子切换 current（Linux 符号链接 / Windows current.txt）
  → 重启矿工并重新应用超频
  → 上报进度和结果
```

中间任何一步失败，当前版本保持不变。

### 回滚

矿机端保留旧版本目录。如需回滚，在矿机详情页下发自定义命令：

```json
{ "type": "rollback_miner", "payload": { "id": "xmrig" } }
```

或在「矿机详情 → 命令」里选「执行自定义命令」粘贴上面的 JSON。

## 5. 版本布局（矿机端）

```
<minerPath>/xmrig/
├── 6.25.0/           旧版本（保留，可回滚）
│   └── xmrig.exe
├── 6.26.0/           当前版本
│   └── xmrig.exe
├── current           → 指向当前版本目录（Linux 符号链接）
├── current.txt       当前版本号（Windows / 符号链接不可用时）
└── version.json      安装记录（版本、入口、安装时间）
```

- Windows：`C:\ProgramData\miner-monitor\miners\`（或采集端配置的 `minerPath`）
- MinerOS：`/opt/mineros/miners/`

采集端启动矿工时优先用 `current` 指向的版本；找不到才回退到旧布局（直接把 exe 放在 `<minerPath>/` 下）。

## 6. 新增币种

控制台「配置 → 币种」，地址 `#/coins`。

### 加一个新币种

点「+ 新增币种」，填：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 币种代号 | 2-12 位大写字母/数字，**不能和内置重复** | `KAS` |
| 币种名称 | 显示用 | `Kaspa` |
| 算法 | 矿工命令行里的 `{algo}` 占位 | `kHeavyHash` |
| 算力单位 | 只影响显示 | `GH/s` |
| 兼容矿工 | 留空 = 自动按算法匹配 | `gminer,srbminer` |

保存后，**飞行表里立刻能选这个币种**，矿机端不需要升级采集端——因为采集端只按飞行表里的命令行模板启动矿工。

### 飞行表写法

新增币种后建飞行表时：

- 币种选 `KAS`
- 矿工选支持它的程序（比如 `gminer`）
- 矿池填 `kaspa-pool.example.com:1234`
- 钱包填你的 KAS 地址
- 命令模板里 `{algo}` 会被替换成 `kHeavyHash`

### 内置币种

`XMR`（RandomX，CPU/GPU）和 `PRL`（PearlHash，GPU）内置，带矿池预设和收益估算；自定义币种只做展示与下发，不内置收益公式。

## 7. 整镜像升级（内核/驱动大版本）

在线升级覆盖 **采集端 / 挖矿程序 / 系统组件**。如果新版换了内核或 NVIDIA 驱动，需要换整镜像：

1. 控制台「系统镜像」页 → 下载新 ISO
2. Windows 管理员 PowerShell：

```powershell
# -KeepConfig 会把 U 盘上的 rig.conf 先备份，刷完再写回去
.\os\tools\flash-usb.ps1 -Iso .\os\dist\mineros-1.0.0-amd64.iso -KeepConfig
```

3. 矿机关机 → 插 U 盘 → 开机

矿机身份、飞行表绑定、挖矿程序版本都在服务器和数据分区里，重刷不会丢。

## 8. 接口与目录

| 接口 | 说明 |
| --- | --- |
| `GET /api/coins` | 币种注册表 + 矿工支持矩阵 |
| `POST /api/coins` | 新增自定义币种 |
| `DELETE /api/coins/:symbol` | 删除自定义币种（使用中会拒绝） |
| `GET /api/updates` | 升级包、矿机版本矩阵、升级记录 |
| `POST /api/updates/upload` | 上传升级包（multipart） |
| `POST /api/updates/push` | 下发升级 `{kind, targetId, version, rigIds}` |
| `GET /api/agent/bundle.tar.gz` | 服务器内置的采集端包（在线自更新用） |
| `GET /api/updates/feed` | 采集端拉取可用升级（矿机密钥） |
| `GET /api/updates/download/:kind/:id/:version` | 下载升级包（矿机密钥或管理员） |
| `POST /api/updates/progress` | 采集端回传进度（矿机密钥） |
| `DELETE /api/updates/:kind/:id/:version` | 删除升级包 |

目录：`updates/`（结构见 `updates/README.md`）

## 9. 排错

**矿机没收到升级命令？**
- 矿机要在线（「矿机版本」页显示在线）
- 升级包平台要匹配（Windows 矿机要有 `win32` 包，MinerOS 要有 `linux` 包）
- 离线矿机的命令会在下次上线时补发，不会丢

**升级记录一直「等待中」？**
- 矿机离线或采集端版本太旧（< 1.1.0）不支持升级命令
- 先下发「采集端」升级，再升级矿工

**进度到 100% 但矿工没变？**
- 看「升级记录」的信息列，会带失败原因
- 检查矿工是否在别处被手动覆盖（`binPath` 直接指向了某个 exe）

**sha256 校验失败？**
- 重新上传，或检查 `updates/<kind>/<id>/<version>/manifest.json` 里的 sha256 是否与文件一致
- 删掉该版本目录后重新生成

**自定义币种矿工起不来？**
- 飞行表的命令模板要匹配该矿工的参数格式（各矿工差异很大）
- 先用「执行自定义命令」在矿机上手跑一遍命令确认
